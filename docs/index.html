HOW IT WORKS · CLICK A STAGE

Bandwidth, combined intelligently.

NetForge does not bond networks at the operating-system level. It binds individual HTTP connections to real interface addresses, schedules work dynamically, and verifies the assembled result before finishing.

01 · PROBECheck the serverRange support, file size, filename, and validators.A 1-byte ranged request confirms whether the server can safely serve independent slices before the download begins.
02 · SPLITQueue byte rangesChunks up to 8 MB enter one shared work queue.Workers lease the next available chunk; no network is trapped behind a fixed share of the file.
03 · ROUTEUse each interfaceConnections bind to recognized local addresses.The OS keeps its normal routing. NetForge selects the local address for each outbound request.
04 · VERIFYReassemble safelyParts merge in order and are checked for length.ETag and Last-Modified checks prevent incompatible server versions from being combined.
CORE CAPABILITIES

Built for real-world downloads.

Dynamic work stealing

Faster connections pick up more chunks instead of waiting behind fixed assignments.

Up to 32 streams

Up to 8 workers per interface keep multiple physical links productive.

Tail racing

Slow final chunks can be raced so one weak connection does not hold the file hostage.

Pause and resume

Completed parts remain on disk and return to the queue only when needed.

Relaunch recovery

Interrupted transfers return as paused downloads after an application restart.

Safe validators

Changed server files are rejected instead of being silently merged into corruption.

Live throughput

Rolling transfer rates and ETA expose what each network contributes.

Progress grid

Every square maps to a chunk and carries its network attribution.

Native signals

Desktop notifications announce completion and errors without leaving the app.
